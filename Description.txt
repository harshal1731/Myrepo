### PROJECT CONTEXT & REQUIREMENTS

1. Architecture:
   - Framework: FastAPI (stateless microservice).
   - Deployment: Docker container, deployed to Azure Container Registry (ACR), hosted on Azure App Service.
   - Storage Constraint: 100% IN-MEMORY (RAM) processing. Persistent volume mounts are NOT used. All uploaded Excel files must be read directly from byte streams using `io.BytesIO` into global Pandas DataFrames. No files are saved to the container's disk.

2. Inputs & Endpoints:
   - Endpoint 1: POST `/api/update-master-data`
     - Accepts a JSON payload containing dynamic master data from .NET and loads it into memory.
     - Decoupled Payload: Renames .NET JSON keys dynamically to internal Pandas names.
       - Vendors: "RegisteredName" (maps to internal "PERSON") and "TradingName" (maps to internal "Vendor name").
       - Properties: "SiteCode" (maps to internal "Yardi code") and "PropertyName1" (maps to internal "Property name").
   - Endpoint 2: POST `/api/upload-expense-report`
     - Accepts optional `expense_file` (UploadFile) of the Expense Distribution report. Must be read with `header=4` (Row 5) and have blank rows dropped.
   - Endpoint 3: POST `/api/process-invoice`
     - Accepts a PDF invoice (UploadFile).
     - Sends bytes to Azure Custom Model 'Greystar_common_logic_v.1.3' (with fallback to 'prebuilt-invoice').
     - Extracts Dutch descriptions and translates them locally to English using the NLLB model.
     - Performs fuzzy matching using `thefuzz` against the in-memory Master Tracker and Vendor List to find Yardi Property and Vendor (Person) codes.
     - Generates a nested, hierarchical JSON payload separating header-level fields from an array of line items (`InvoiceItems`), plus two root-level wrapper fields ('vendor_file_name', 'status').

3. Business Rules & Nested ETL Mapping:

   A. Header-Level Fields (inside `etl_data`):
   - 'PROPERTY': Yardi property code matched from Master Tracker.
   - 'PERSON': Yardi vendor (PERSON) code matched from Vendor sheet.
   - 'OFFSET': Default to '11020000'.
   - 'DUEDATE': If vendor starts with 'Greystar Netherlands', same as Invoice Date. Otherwise, Invoice Date + 30 days. Format: DD/MM/YYYY.
   - 'DATE': Invoice date (formatted as DD/MM/YYYY).
   - 'POSTMONTH': Derived from Invoice Date as MM/YYYY.
   - 'ACCOUNT': Mapped dynamically from the uploaded Expense Report using keyword/semantic matching against the English description.
   - 'ACCRUAL': Default to '21010000'.
   - 'REF': Extracted Invoice Number.
   - 'SEGMENT1' to 'SEGMENT12', 'EXCHANGERATE', 'EXCHANGERATEDATE', 'TAXAMOUNT1', 'TAXAMOUNT2': All default to "NA".
   - 'FROMDATE' & 'TODATE': Extracted from English description; if missing, defaults to Invoice Date (DD/MM/YYYY).
   - 'EXPENSETYPE': Default to "Expense (Opex)".
   - 'DETAILNOTES': English translated invoice description.
   - 'DISPLAYTYPE': Default to "NLVatApplicablePayable".
   - 'ISCONSOLIDATECHECKS': Default to -1.
   - 'DETAILVATTRANTYPEID': Default to "apresex".
   - 'DETAILVATRATEID': If Tax Amount is 0, "Zero Rated", else "Uksr".
   - 'INTERNATIONALPAYMENTTYPE': Default to "EFT" (or "Cheque" if IBAN begins with 'GB' or currency is non-Euro).

   B. Line-Level Fields (inside `InvoiceItems` array):
   - 'TRANNUM': Incremental sequence number starting at 1 per line item.
   - 'NOTES': English translated description of the specific line item.
   - 'AMOUNT': Line-level amount (numeric).
   - 'DETAILTAXAMOUNT1': Line-level tax amount (numeric).

4. Validation & Status Rules:
   - If any mandatory field ('PROPERTY', 'PERSON', 'AMOUNT', 'ACCOUNT', 'REF') is missing, "NA", "UNKNOWN", or 0.0, the root level 'status' field must be set to "In Review".
   - Otherwise, 'status' must be set to "Ready to Post".
